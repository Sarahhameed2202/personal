RAG pipeline inspector — every step, actually computed

Nothing here is faked. The chunker splits real text, the embedder produces real vectors, and cosine similarity is calculated in the browser. Change something upstream and watch everything downstream go stale, which is the part most diagrams leave out.

01

Documents

Your knowledge source. Edit freely — this is the only content the model will be allowed to answer from.

02

Chunk

Documents are cut into passages small enough to fit a prompt and specific enough to match one question. Overlap stops a sentence being severed mid-idea.

No chunks yet. Set a size and press Split into chunks.
03

Embed

Each chunk becomes one fixed-length vector. Same chunk in, same vector out — and the query will have to go through this identical function later.

04

Index

Vectors plus their original text go into the store. Everything up to this point happens offline, before any user exists.

Waiting on step 03.
05

Retrieve

The question is embedded by the same function, then compared against every stored vector. Highest cosine scores win.

Waiting on step 04.
06

Augment

The retrieved text is pasted into the prompt as context. This is the entire trick — no weights change, the model simply gets better material to read.

07

Generate

The answer is composed from the supplied passages, with citations back to the chunks that produced it.

Honest caveat about the embedder: real systems use a trained neural model that maps meaning to geometry, so car and automobile land near each other. This one hashes weighted terms into buckets, so it only matches shared vocabulary. The pipeline, the maths and the failure modes are identical — the semantics are shallower. When retrieval here misses an obviously relevant chunk because you used a synonym, you have just reproduced exactly why hybrid search and rerankers exist.
